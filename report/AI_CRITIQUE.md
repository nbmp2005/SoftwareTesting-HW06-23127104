# AI Critique (Mandatory, 200–300 words)

During this assignment, I used OpenAI Codex to extract the FR-02 contract, generate login test candidates, organize coverage, and create Postman assertions. The generated suite was useful for standard partitions, the 0/1/2/3 failure boundary, the 29/30/31-second lock boundary, response schema, and basic token syntax. However, its security and sequence reasoning remained incomplete. It verified that a JWT had three decodable segments but did not try an `alg=none` forged token against a protected endpoint. It also treated `U-A` as a fixed identity without questioning whether email case normalization and the failure-counter key were consistent.

I detected these gaps by combining threat modelling with sequence and differential testing, rather than reviewing each endpoint and boundary independently. I added `FR02-H-001` through `FR02-H-005` for forged-JWT rejection, password-reset interaction with an active lock, case-variant counter bypass, requests injected during the lock interval, and forgot-password enumeration. Reviewing these cases also exposed a weakness in my own initial oracle design: several expectations were written as “if A, then …; if B, then …”, which could not produce a deterministic verdict. I therefore declared explicit working assumptions for fixed lock duration, lock persistence across password reset, account normalization, and non-revealing forgot-password responses.

I also corrected the claim that returning `resetToken` is automatically a SEC-01 bug. The current API specification explicitly documents that field, while SEC-01 concerns plaintext password storage. It remains a security concern for requirement review, but not a confirmed defect without a conflicting authoritative rule. No execution has occurred yet, so none of these risks is reported as an actual bug. The main lesson is that AI expands coverage efficiently, but a human must define defensible oracles, examine cross-feature interactions, and separate suspicious design from verified requirement violations.
